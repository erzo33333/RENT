# RENT

Репозиторий для командного проекта.

## О проекте

Тема: Разработка веб-приложения для учета недвижимости арендодателей.

Назначение: информационная система учета недвижимости предназначена для арендодателей, сдающих в аренду объекты недвижимости. Система решает проблему разрозненного учета и позволяет собственнику контролировать бизнес в одном окне.

## Структура документации

Вся проектная документация находится в папке [`docs/`](docs/).

| Документ | Содержание |
|----------|-----------|
| [`docs/001_architecture_style.md`](docs/001_architecture_style.md) | ADR-001: выбор архитектурного стиля — модульный монолит, обоснование и последствия |
| [`docs/functional.md`](docs/functional.md) | Функциональные требования: управление объектами недвижимости, проживающими, договорами, платежами, имуществом, показаниями счётчиков, уведомлениями, отчётностью и доступом |
| [`docs/non_functional.md`](docs/non_functional.md) | Нефункциональные требования: производительность, доступность и надёжность, безопасность, масштабируемость, удобство использования, сопровождаемость, совместимость |

```
docs/
├── 001_architecture_style.md   # ADR-001: архитектурный стиль
├── functional.md               # Функциональные требования (FR)
└── non_functional.md           # Нефункциональные требования (NFR)
```

ADR-001 обосновывает выбор модульного монолита и опирается на нефункциональные требования по сопровождаемости, производительности и масштабируемости. Функциональные требования описывают, что делает система, а нефункциональные — как она должна работать; вместе они служат основой для проектирования модулей.

ADR-файлы ведутся по шаблону: статус, дата, контекст, рассмотренные варианты, решение, обоснование, последствия, связь с NFR. Требования используют префиксы `FR-L-*` (арендодатель), `FR-T-*` (арендатор) и `NFR-*` (нефункциональные). При добавлении новых разделов документации этот README обновляется.
